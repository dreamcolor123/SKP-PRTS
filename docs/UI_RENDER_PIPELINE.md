# 渲染流水线与默认配色

本轮承接用户 Logo 替换，并修复此前“遮挡同帧提交”引入的掉帧回归。

## 根因与修复

原实现虽然采用异步 GPU 像素读取，但整帧模拟与绘制仍等待该读取完成。移动 GPU 的读回和同步栅栏延迟因此成为动画吞吐上限，不能仅凭 JavaScript RAF 频率判断流畅度。

新增 `FolderFramePipeline`，使用三个有界槽保存完整分辨率颜色、独立遮罩像素和投影快照。GPU 在后台准备新帧，输入和动画模拟继续；只显示同一槽的颜色、遮罩、标题和透视。迟到或过期帧丢弃，读取失败保留最近完整帧。槽满时跳过新的 GPU 提交，不阻塞操作，也不无限分配缓冲。

颜色仍经原材质、透明度、抗锯齿和后处理路径绘制，再在 GPU 内复制。最终 blit 不重复色调映射或颜色空间转换。原始画质和 SUPER PERFORMANCE 均保留其既有渲染语义，流水线本身不降低分辨率。

物理遮挡继续使用实际几何深度，额外以相机至卡面的空间范围排除不可能遮挡的地板、下沉邻件。没有潜在遮挡时不执行 GPU 遮罩读回。数值裁剪路径仅在遮罩或卡面尺寸变化时更新。

三个颜色槽的 RGBA8 内存为 `宽 × 高 × 4 × 3`，另有小尺寸遮罩缓存；例如 618×1300 颜色合计约 9.2MiB。代价是有限的呈现延迟，而不是每帧停止推进。画质仍可手工调整。

## 默认与颜色

- 新安装或无已保存偏好时，Web 与原生界面默认暗色，SUPER PERFORMANCE 默认开启。已保存的亮色或关闭设置不被覆盖。
- 原模型的 `Amber_Optical_Inlay`、`Champagne_Index`、`Index_Inlay` 与 Orange 类装饰统一改为淡紫色；不改变几何和内部光学结构。
- 普通实色操作控件使用 `#d8c5f2` 底色、`#21182e` 文字，悬停 `#e5d8f7`。错误、危险操作及健康状态警示保留语义颜色，毛玻璃不染成紫底。
- 新 Logo 的来源、精确运动对照和系统启动行为见 `UI_USER_LOGO.md`。

## 倾斜背景边界

暗色状态的雾终值原为 `#263136`，场景背景为 `#11181b`。地面远边虽已完全雾化，但在手机倾斜时会进入画面，形成明显斜线。现在让暗色雾收敛至同一背景色；保留原 200×200 地面、相机范围和视差幅度，不增加几何或绘制批次。亮色和原始开场的雾/背景本来一致，仍保留。

## 验证口径

性能对照使用同一视口、浅色、SUPER PERFORMANCE 和数据，统计真实呈现帧而非 RAF。旧基线含 Logo SVG 的 XML 属性缺值，测量时仅在内存规范化该属性以恢复模型贴图；原构建未改。新构建已修复，规范化计数为零。失败尝试与报告保留，不作为性能数据。

检查包括有界槽生命周期、GPU 乱序完成与故障、颜色和真实几何遮挡逐像素对照、快速导航中的同步、默认偏好/保存偏好、淡紫按钮对比度，以及 Android 安装启动。最终数据与原始命令以事务 `VERIFICATION.txt` 为准；桌面受控延迟结果不等于用户手机帧率。
