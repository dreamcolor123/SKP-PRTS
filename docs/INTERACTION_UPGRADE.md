# 档案正面交互优化

本轮沿用既有 RhineLabUI 的开场、玻璃、机械结构、灯光、材质、波浪、抽取与声音。最后的用户补充优先于早期的平面展开方案：工作控件必须始终贴在倾斜档案块的正面，不能在动画结束后平铺到屏幕。

## 正面透视

`FolderFacePanel` 是可操作的 DOM 层，四角来自 `ArchiveScene.projectCard()` 的模型局部坐标 `(-2.28,3.4)`、`(2.28,3.4)`、`(2.28,0.18)`、`(-2.28,0.18)`，与现有正面贴标共用 `z=0.255` 平面。

每次实际绘制都把四角经过模型世界矩阵和相机投影，再用 `hudQuadMatrix()` 生成 CSS `matrix3d`。文字、边框、滚动区和按钮共用该矩阵，浏览器命中测试随透视一起变化。不再插值到屏幕矩形，也不在减少动态模式下取消透视。

内容布局保持正面物理宽高比 `4.56:3.22`，避免把竖屏页面压扁到横向平面。日常工作态仅调整相机取景，使正面可读；开场和阵列浏览沿用原相机。WebGL 不可用时才使用平面回退。

用户随后要求真实前后遮挡和毛玻璃，已进一步加入 `FolderDepthMask`：以真实场景几何绘制离屏深度，排除选中模型自身，再以相同深度测试绘制正面可见区域。将 GPU 结果反投影回控件局部坐标，形成随档案运动更新的 CSS mask。被遮挡区域不接收业务点击，手势转交背景场景。

控件底色透明度为 30%，叠加 `backdrop-filter: blur(12px) saturate(.75)`；只模糊背后的场景，不模糊正文。前景遮挡物移到后方时，GPU 测试的可见比例由 50% 恢复至 100%，DPR 1/2 一致。实际抽取过程可见区域从约 0.4% 逐步恢复到 99%以上；冻结画面对比确认背景模糊改变了真实输出像素。

## 直接交互

- 常驻概览、授权、模块、市场、设置五个中文分区，映射原物理列。
- 开场完成或跳过后进入概览正面；列表、真实状态、字段、主操作和更多操作直接位于档案正面。
- 授权支持添加/撤销；模块支持安装、条目 WebUI；市场支持直接安装。下载横条跨分区显示，不受搜索过滤影响。
- 搜索索引包含功能标签与别名、应用名、包名、模块 ID，功能结果直接打开原生流程。
- 设置集中内核设置、诊断与日志、外观声音、本地定制和关于；上方外观入口指向同一外观设置。
- 保留原 `rhine-saved` 常用 ID、分区查询、列表滚动和条目返回位置；旋转/重建通过原生 ViewModel 恢复展示状态，不重放业务动作。
- 保留阵列浏览与背景拖动；工作区内箭头键、滚动和输入由控件接管，返回按条目、分区、概览、退出依次处理。
