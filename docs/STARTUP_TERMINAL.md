# 终端入口与首次配置

模式选择和首次 Root Key 配置共用原生 `StartupTerminalFrame`：紧凑 SK 标识、分段编号、细线与微弱刻度、20sp 标题和 12-14sp 主要控件。入场使用一次性的 480ms 线条展开与轻微淡入；关闭系统动画时直接显示终态，不增加持续渲染或模糊开销。

两种管理器的首次配置使用相同入口风格，配色跟随当前原生外观。旧 Compose 的主页、设置及后续打开的 Root 配置弹窗保持原版；只有首次流程使用新入口。取消或配置完成后记录会话完成状态，旋转保留；无已存密钥的下一次冷启动仍允许配置。

首配继续调用原 ViewModel：Boot/热启动、导入、导出、取消和保存顺序不变。Root Key 留在原生输入，密码遮罩、自动纠错关闭；导入脚本后禁用手工改密钥，忙碌时禁用模式与操作。底部操作区独立于正文滚动，随 IME 安全区抬起；不会因为按键盘完成键自动提交 Root 配置。

NavHost 与系统回调始终保持挂载，首次页面只替换 main 路由内容。输入错误 Snackbar 位于操作区上方，不覆盖取消或确认。已保存密钥时不进入这两个表单，后续完整 MG 与三维开场未修改。

验证：`StartupTerminalTest` 使用假回调检查选择去重、失败重试、密码与导入状态、忙碌、8种布局和真实键盘；`DualUiModeTest` 检查实际启动链与模式切换；`SystemBarThemeTest` 保留前次系统栏回归。截图与最终运行结果以事务目录验收记录为准，不把布局模拟视口视为真机测试。
