# 档案高度、悬浮导航、方向视差与设备状态

本轮继续修改 `D:/SKP-PRTS-UI-transaction/MODIFIED_FILE`，原项目不改动。保留上一轮持续透视、GPU 前景遮挡和毛玻璃。

## 视觉与交互

- 日常工作态档案高度为原来的 **1.65 倍**。阵列、选中档案、归位档案、抽取高度、相机取景和剔除边界同步调整；开场仍使用原尺寸与时间轴。内部光学核心保持纵横比例。
- DOM 控件使用同一模型矩阵投影，布局高度随物理正面增加，不把字体垂直拉伸；横屏使用更窄的局部布局与次操作菜单，避免字号被大幅缩小。
- 导航改为距边缘至少 16px 的悬浮玻璃岛，22px 背景模糊、63% 玻璃底色、细边框与柔和阴影。手机为底部五分区，宽屏/短横屏为侧边岛；选中底板以 260ms 可中断动画移动。
- 背景卡面、标题、正文、查询与按钮区采用不同的投影深度。卡面 z=0.255，正文层 z=0.285，标题 z=0.32，查询 z=0.34，操作区 z=0.37。额外微小控件偏移和阴影使层次轻微可见，正文不作动态模糊。

## 方向传感器

Android 使用 Game Rotation Vector，缺失时回退 Rotation Vector；两者都缺失则保持静态。首次读取和每次恢复重新校准为中立姿态，按显示方向映射轴。

输入采用 0.006 rad 死区、160ms 低通滤波、12° 输入满量程，最多 30Hz，经离线 MessagePort 发送 `{type:"motion",version:1,x,y}`。相机使用约 0.34°/0.29° 的最大微扰，导航偏移不超过 0.4px，控件附加偏移不超过 0.55px。前端继续平滑输入。

后台、页面隐藏、原生遮挡、Web 弹窗、模型查看器、减少动态和渲染错误均暂停采样/显示，返回后校准。不新增权限，不触发逐帧 Compose 重组，不向网页提供原始传感器记录。

传感器数学、消息输入、微扰幅度与减少动态通过自动化检查。模拟器及浏览器不等同于物理手机手感；真机方向传感器、高刷、GPU 和温升仍需用户设备测试。
